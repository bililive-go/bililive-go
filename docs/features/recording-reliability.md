# 直播录制与 FLV 后处理容错

## 抖音仅录制音频

复用直播间 `audio_only` 开关，默认关闭；输出 AAC，并自动使用 FFmpeg。

优先从配套 biliLive-tools 的 `dev.sources[].streams[]` 中选择 `quality=ao`、地址带 `only_audio=1` 的 HTTP(S) 线路，保留签名原文。

- 无纯音频线路或工具不支持扩展查询时，沿用视频取流接口，由 FFmpeg 只保存音轨。
- 纯音频拉流失败或输出为空时，下一轮尝试原视频流提取音频；十分钟后才重试纯音频线路。正常停止不触发回退。
- 回退模式仍下载完整视频流，因此只节省输出空间，不节省网络流量。
- 仅抖音音频模式强制 FFmpeg 并关闭 FLV 代理分段；其他平台沿用原下载器和代理配置，视频模式行为不变。

## B 站主播资料请求失败

主播资料请求携带已配置的 Cookie。成功缓存名称六小时，失败后五分钟再试。主播资料 HTTP 412、业务错误、无效响应或网络错误不再阻断已成功获取的房间状态；优先使用缓存名称，否则临时使用房间号。房间状态接口失败仍报错。

## FLV 修复安全

修复在同一文件系统的独立 `.bililive-fix-*` 目录运行，记录命令、标准输出和标准错误。单文件结果通过验证并刷新数据后才重命名替换原片，不提前删除原片；多分段额外逐流核对 AAC/AVC 编码内容、包边界、顺序及每包生效的编码头，允许重建时间戳。完全一致后发布到原录像目录，命名为 `.part001.flv` 等；全部分段刷新并发布、目录刷新成功后才删除原片。同名文件不覆盖，发布失败撤销本次链接并保留原片。成功后清理多分段工作目录；清理失败输出警告。进程在发布途中被强制终止时可能留下部分链接及原片，重试遇到同名文件保守中止。

验证包括完整 FLV 标签边界、PreviousTagSize、明显时间戳倒退、90% 总体积，以及各音视频流至少 98% 的包数和覆盖时长。这些检查不等同于逐帧解码或直播源内容完整性保证。

低于 90% 时仅允许单文件 H.264 填充删除特例：流式哈希核对所有非填充 NAL、音频、编码头、结束标记、逐包边界、DTS/CTS，必须完全一致；只排除合法 type 12 填充数据，并要求填充数量与字节数确实减少。文件缩小量不得超过已验证删除的填充字节（含长度前缀）；允许重建索引使封装元数据增大。核验证据保存在 `filler-verification.json`。

无法验证、格式不支持或存在其他内容差异时，不享受体积特例。失败清理本次部分 FLV 产物、保留诊断；原片结构可读时记录警告继续后处理，并保护它不被内置清理或删除源文件阶段移除。原片缺失、结构检查失败或任务取消仍返回错误。工具执行超时为 30 分钟。

不迁移录制配置，也不自动重跑历史任务。用户自定义外部命令仍由命令本身决定文件操作。

所有校验共用一个 FLV 标签读取器，复用标签缓冲；输出结构统计与对应指纹同遍完成。普通单文件只做基础扫描，填充特例和多分段才额外读取原片计算指纹。编码内容验证不等同于逐帧解码或音画同步验证。新增测试仅保留 `src/tools/recording_core_test.go`，覆盖 412、填充删除、失败保留、取消、截断、多分段发布及冲突回滚。
