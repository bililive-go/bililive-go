# 直播录制与 FLV 后处理容错

## 抖音仅音频

复用现有 `audio_only` 开关，默认关闭，不迁移或改写配置。开启后输出 AAC，使用 FFmpeg 并关闭 FLV 代理分段；其他平台沿用原有下载器及代理配置。

优先选择 biliLive-tools 返回的 `quality=ao`、带 `only_audio=1` 的 HTTP(S) 地址，保留签名。房间无可靠音频线路或工具不支持时，使用原视频流提取音频。只有独立音频流能节省下载流量；视频回退仍下载完整视频。

纯音频在五秒内失败，或结束后未产生可解码音频时，下一轮重试改用视频流提取音频，十分钟后再尝试独立音频。可用性检查只解码本地文件开头一帧、最多等待五秒；检查工具不可用或超时不据此判定源不兼容。正常停止不触发回退，持续录制且输出有效时的普通断流也不触发冷却。原视频源或 FFmpeg 本身失败，仍沿用原有重试机制。

保存 `audio_only` 后无需重启；下一轮取流读取已提交配置，并固定该轮的音频模式，保证取流、下载器和文件格式一致。正在下载的任务不主动中断；页面返回已保存选项，不改写录制共享缓存。此修复仅针对音频开关，不代表所有配置均可热更新。

## B 站主播资料 412

请求携带已配置 Cookie，成功名称缓存六小时，失败后退避五分钟。资料接口失败不丢弃已经获取的房间状态：优先使用缓存名，否则临时使用“房间 + 真实房间号”。房间状态接口本身失败仍报错。

缓存仅在进程内保存，首次失败可能使录像路径采用临时名称；此处理避免资料接口阻断开播检测，不保证上游不再返回 412。

## FLV 修复与原片安全

不修改录制配置。工具在原录像旁的独立 `.bililive-fix-*` 目录生成结果，超时三十分钟或取消即终止子进程。命令及 stdout/stderr 保存在该目录，错误附带输出末尾和诊断路径。

### 校验与替换

- 输出必须是本次目录内不重复的普通文件；完整扫描 FLV 标签，检查边界、PreviousTagSize、媒体包和明显时间戳倒退。
- 可读原片只有在逐流编码包、包边界、顺序和生效编码头完全一致时才允许替换，允许工具重建时间轴。当前内容验证支持 AAC/AVC，不支持的编码保留原片。封装元数据允许重建。
- 单文件删除 H.264 填充数据可作为内容比较的唯一例外：音频、非填充 NAL、编码参数、包边界、DTS/CTS 和结束标记必须一致；只排除合法 type 12 填充 NAL，并要求填充确实减少、净缩小量不超过删除的填充字节数（含长度前缀）。低于原片 90% 体积时也必须通过此严格校验，并在工作目录记录核验结果；多分段不享受填充删除例外。
- 截断或 PreviousTagSize 错误等结构损坏不阻止工具运行，但无法证明内容完整，因此严格检查修复产物后单独发布为 `.repaired.flv` 或 `.repaired.part001.flv`，始终保留原片。
- 所有验证共用流式标签读取器，复用缓冲区，不将整场录像读入内存；发布前再次确认原片大小和修改时间未变，并检查任务取消状态。结构与编码内容校验不等于完整解码或音画同步证明。

单文件先刷新产物，建立原片硬链接备份并同步目录，再以 rename 替换；替换后的目录同步失败时保留备份。多分段发布到原录像目录的 `.part001.flv` 等路径，刷新所有分段及目录后才删除原片，再同步目录。分段重试仅复用逐字节一致的普通文件；冲突文件不覆盖，失败只撤销本次创建的链接，不删除复用文件。

### 清理与失败处理

成功后清理本次工作目录和临时备份；清理失败告警。失败只清理工作目录内的 FLV 半成品，保留诊断及必要原片备份。异常退出可能留下文件，不自动删除历史工作目录或录像。

工具或验证失败且原片结构可读时，记录警告和 `fix_flv_warning`，继续处理原片；`preserve_original` 禁止内置清理及删除源文件阶段自动删除它。任务可能显示完成，需查看阶段日志确认是否回退。原片不存在、不可读且修复失败、或任务取消，仍按失败/取消处理。用户自定义外部命令由命令本身控制。

新增回归仅保留 `src/tools/recording_core_test.go`，覆盖 412 退避、FLV 内容保护与发布恢复、音频输出检查及保存音频配置后的下一轮生效/当前取流快照保护；原仓库测试不变。不迁移录制配置，不自动重跑历史任务。
